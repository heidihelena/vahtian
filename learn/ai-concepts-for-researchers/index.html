ML, LLM, RAG, GraphRAG, DAG, agents — a researcher's map

Every research-AI tool is built from a short stack of ideas. Each idea does one job well and leaves a specific gap. This is one page for the whole stack: what each is for, and — the part the marketing skips — what each does not guarantee.

After this guide you will be able to:

  • Say what machine learning, LLMs, RAG, knowledge graphs, GraphRAG, DAGs, and agents each actually do.
  • Name the gap each one leaves — the thing it does not establish.
  • See why stacking all of them still does not produce scientific correctness.

The ideas build on one another in roughly this order. You can read straight through, or jump to the concept you came for.

1. From rules to machine learning

Older software followed rules a person wrote by hand: if this, then that. Machine learning (ML) flips it around. You give the system examples — inputs paired with known answers — and it fits a function that reproduces those answers and, you hope, generalizes to new inputs. A model predicting readmission from a patient's record is ML: nobody wrote the rule, the model inferred it from past cases.

What it buys you is pattern detection at a scale no rule-writer could match. What it does not buy you is causation. A model can learn that an outcome co-occurs with a feature without that feature causing anything — the textbook case is the model that keys off a scanner's ID because sicker patients happened to use one machine. ML predicts; it does not explain, and it does not certify that the pattern is real science rather than an artefact of how the data were collected.

2. What an LLM predicts

A large language model (LLM) is a particular kind of ML model trained on text. Its one native task is narrow: given the text so far, predict plausible next text. Everything it appears to "do" — summarize, answer, translate — is that one prediction task applied cleverly.

This is why fluency and accuracy come apart. An LLM will write a confident, well-formed sentence whether or not the claim in it is supported, because its objective rewards plausibility, not truth. A summary of a paper can read perfectly and still misstate the finding. The gap the LLM leaves is factual support: it generates language, not verified claims.

3. What retrieval-augmented generation adds

Retrieval-augmented generation (RAG) tries to close part of that gap. Before the model answers, the system retrieves relevant text — from your document vault, a paper set, a database — and puts it in front of the model to work from. Instead of answering from memory alone, the model answers from retrieved passages, and can quote them.

This genuinely helps: it grounds answers in a source you control and can inspect, and it keeps the model current with material it was never trained on. But RAG adds two new places to go wrong. Retrieval can surface the wrong passage, and the model can still misread the right one. RAG does not guarantee correct retrieval or correct interpretation — it just makes both visible enough to check.

4. Why ordinary RAG loses relationships

Standard RAG treats your corpus as a bag of text chunks and retrieves whichever chunks look similar to the question. That works for "what does this passage say" and fails for "how do these things connect". The structure that matters in research — this claim cites that source, this result comes from that dataset, this conclusion depends on that assumption — lives between chunks, and chunk-similarity retrieval cannot see it.

So a question like "which conclusions rest on the study that was just retracted" is exactly the kind ordinary RAG handles badly: the answer is a chain of relationships, not a similar-looking paragraph. The relationships were never represented, so they cannot be retrieved.

5. What a knowledge graph represents

A knowledge graph makes the relationships first-class. Instead of loose text, you have nodes (a claim, a source, a variable, an analysis) joined by typed edges (cites, derived-from, supports, contradicts). Now "what depends on this source" is a graph you can traverse, not a search you hope works.

The catch is that a graph represents relationships; it does not adjudicate them. An edge labelled supports asserts a relationship — it does not make the support real. A knowledge graph does not guarantee that its relations are true; it guarantees only that they are written down explicitly enough to be checked and argued with.

6. What GraphRAG adds

GraphRAG is RAG that retrieves through the graph. Rather than fetching similar chunks, it follows edges — pull this claim, then the sources it cites, then the analyses those sources rest on — so the retrieved context is a connected neighbourhood of evidence instead of a pile of look-alike passages. For "trace everything downstream of X", this is the right tool.

But retrieving a connected subgraph is not the same as judging it. GraphRAG can hand you the claim, its citation, and the cited passage side by side — and it still does not establish that the evidence supports the conclusion. It assembles the material for that judgment; the judgment is a separate act.

7. What a directed acyclic graph controls

A directed acyclic graph (DAG) is a graph with direction and no cycles: work flows one way and never loops back on itself. Used as a workflow, it encodes dependencies — build the analysis dataset before the model, run the model before the table — so steps happen in a valid order and independent branches can run in parallel.

A DAG guarantees the order is coherent. It says nothing about whether the order is right for the science. You can build a perfectly valid DAG around the wrong estimand, an inappropriate comparator, or a model that should never have been fit. The DAG does not guarantee that the workflow is scientifically appropriate — only that it is internally consistent and executable.

8. How agents use tools and workflows

An agent is an LLM given tools and a loop: it decides which action to take, takes it, observes the result, and decides again. With the right tools it can retrieve a source, run an analysis, and export a table — chaining steps toward a goal instead of answering a single prompt.

Capability is not authority. An agent can execute a consequential step — accept an inclusion decision, finalize a risk-of-bias rating, sign off on an interpretation — without being the right actor to make that call. The gap an agent leaves is appropriate authority and judgment: doing the action and being entitled to decide it are different things, and only the second protects a research record.

9. Why provenance and audit trails matter

Notice the pattern. Every technique above leaves a gap, and every gap is closed the same way — by a person, on the record. That is what provenance and an audit trail are for. Provenance is the answer to "where did this come from"; an audit trail is the answer to "who decided what, on what evidence, and when".

This is the layer that makes the rest defensible. A retrieved passage is only as good as the record of which source it came from. A supports edge is only trustworthy if you can see who assessed it and why. An agent's action is only acceptable if the record shows a qualified human cleared it. None of the earlier techniques record this by default; it has to be designed in. When it is, "why should I believe this?" has a concrete answer instead of an appeal to the model.

10. Why none of these proves scientific correctness

Stack the whole thing — ML under an LLM, grounded by GraphRAG over a knowledge graph, orchestrated by a DAG, driven by an agent, all of it logged with provenance — and you have a powerful research system. You still do not have a truth machine.

Each layer establishes something narrower than it looks: ML finds patterns, not causes; an LLM produces fluent text, not supported claims; RAG grounds an answer without guaranteeing the grounding is right; a knowledge graph states relations without making them true; GraphRAG gathers connected evidence without judging it; a DAG orders work without knowing if the work is sound; an agent acts without holding the authority to decide. Provenance records all of it faithfully — and a faithful record of a flawed analysis is still a flawed analysis.

Scientific correctness is not a property any of these techniques can deliver, because it is not a computational property at all. It is a judgment made by qualified people, about a specific claim, in light of specific evidence and specific assumptions. The most an honest system can do is make that judgment easier and better-documented: put the claim next to its source, show the dependency chain, record who decided, and flag what still needs review. That is the job. Certifying the truth is not.

The one line to keep. These tools decide where to look and what to show you. They do not decide what is true. Any research tool — Vahtian included — that blurs that line is selling the wrong thing.
